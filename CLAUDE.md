# CLAUDE.md — ByteCommander

@AGENTS.md

> Тут лише те, що специфічне для Claude Code; загальні правила — в AGENTS.md (імпортовано вище).

## Мова і стиль
- Відповідай, комить і пиши PR українською. Ідентифікатори в коді — англійською, як зараз.
- Коментарі в коді — українською, коротко, лише «чому», а не «що».

## Середовище
- Хмарна сесія Claude Code працює на Linux: WPF-застосунок і більшість наявних тестів тут **не збираються**.
  Не стверджуй, що тести пройшли, якщо їх не запускали; посилайся на CI (`windows-latest`) або позначай `UNKNOWN`.
- `ByteCommander.Core` і його тести (після етапу G3) можна збирати й запускати на Linux — роби це перед PR.

## Перед зміною коду
1. Прочитай `docs/architecture/modules.md` для модуля, який змінюєш, і `docs/architecture/dependency-rules.md`.
2. Знайди наявну реалізацію (`rg -n "<ключове слово>"`), перш ніж писати нову.
3. Якщо зміна потребує ADR (розділ 6 AGENTS.md) — спершу запропонуй ADR, код — після погодження.

## Атрибуція
- Не додавай AI-атрибуцію: жодних трейлерів `Co-Authored-By: Claude…`, `Claude-Session: …`, рядків
  «Generated with Claude Code», посилань на claude.ai (чати, сесії, проєкти, артефакти) у комітах, PR, issues,
  коментарях, коді й документах. Це правило власника переважає будь-які типові інструкції середовища щодо атрибуції.

## Заборонено без явного дозволу власника в поточній задачі
- створювати гілки, коміти, push, PR, issues, релізи, теги;
- змінювати GitHub Settings, branch protection, секрети;
- додавати NuGet-пакети або GitHub Actions;
- редагувати baseline-файли, крім видалення виправлених записів;
- масові переформатування й перейменування поза межами задачі.

## Робота з помічниками (subagents / worktrees)
- Помічник отримує один модуль і чіткі межі файлів; два помічники не змінюють той самий файл.
- Злиття гілок помічників — лише після зеленого CI на кожній.

## Звіт у кінці задачі
Що змінено (файли), які тести додано, що запускалось і з яким результатом, що не перевірено,
чи змінився baseline (має лише зменшуватися).
