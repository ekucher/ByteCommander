# ADR-0001. File Provider Architecture

- Статус: Proposed
- Дата: 2026-11-21
- Джерело: цільова архітектура, частина 2 аудиту (артефакт від 21.11.2026)
- Уточнюється: ADR-0017 (узгодження можливостей на рівні кореня/сесії, `ApiVersion`)

## Контекст

14 файлів напряму викликають System.IO; шлях — рядок Windows; 42 порівняння імен OrdinalIgnoreCase `CONFIRMED`.

## Проблема

Неможливо додати SFTP/SMB з обліковими даними/архіви без розгалужень у кожній команді.

## Розглянуті альтернативи

(a) if (remote) у кожному місці; (b) монтувати віддалене як диск (WinFsp/SSHFS); (c) власний IFileProvider з VfsPath; (d) System.IO.Abstractions.

## Рішення

(c). (d) відкинуто: це абстракція над System.IO з Windows-семантикою шляхів, без async і можливостей. (b) — зовнішній драйвер і права адміністратора.

## Наслідки

Панель і операції працюють через інтерфейс; кожен провайдер задає NameComparer; SMB лишається на системному клієнті Windows (UNC через локальний провайдер + Win32 для облікових даних і переліку шар).

## Ризики

Регресії навігації; надмірна абстракція. Пом’якшення: лише потрібні методи, локальний провайдер першим.

## План міграції

Покроково: LoadItems → ListAsync; потім операції; потім пошук і порівняння.

## Перевірка (тести)

Contract-тести, однакові для кожного провайдера (in-memory, local, SFTP у контейнері).
