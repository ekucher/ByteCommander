# ADR-0002. Operation Engine

- Статус: Proposed
- Дата: 2026-11-21
- Джерело: цільова архітектура, частина 2 аудиту (артефакт від 21.11.2026)

## Контекст

OperationRunner створює незалежне вікно на кожну операцію, без черги `CONFIRMED`.

## Проблема

Немає пріоритетів, паузи, історії, відновлення; дві операції можуть конфліктувати.

## Розглянуті альтернативи

(a) Розширити OperationRunner; (b) OperationQueue з Channel<T> і станами; (c) Windows IFileOperation для всього.

## Рішення

(b), повторно використовуючи логіку FileOperation як виконавця. (c) — лише для кошика.

## Наслідки

Operations Center замість окремих вікон (вікно прогресу лишається опційно); стани Queued/Running/Paused/Failed/Done/Canceled; журнал JSONL у %LOCALAPPDATA%.

## Ризики

Конфлікти паралельних задач над одним шляхом → блокування за префіксом шляху.

## План міграції

Спершу черга з паралельністю 1 і поточним UI; потім Operations Center.

## Перевірка (тести)

State machine unit-тести; 10+ задач; скасування під час заміни; disk full через малий VHD/subst-том.
