# ADR-0003. Synchronization State Model

- Статус: Proposed
- Дата: 2026-11-21
- Джерело: цільова архітектура, частина 2 аудиту (артефакт від 21.11.2026)

## Контекст

Є лише порівняння «тут і зараз» `CONFIRMED`; двостороння синхронізація у спеці потрібна.

## Проблема

Без попереднього стану неможливо відрізнити «видалено зліва» від «створено справа».

## Розглянуті альтернативи

(a) Без стану (лише one-way); (b) знімок метаданих останньої успішної синхронізації (шлях, розмір, mtime, хеш опційно) на профіль; (c) журнал змін ФС (USN) — лише локально.

## Рішення

(b), зберігати в SQLite (Microsoft.Data.Sqlite) або JSONL на профіль; one-way режими працюють без стану.

## Наслідки

Конфлікт = змінено з обох боків після знімка; видалення = було в знімку, зникло з одного боку. Перейменування — евристика (розмір+mtime+хеш), лише як пропозиція.

## Ризики

Знімок застарів/пошкоджений → режим «перше порівняння» без видалень.

## План міграції

Новий функціонал.

## Перевірка (тести)

Таблиця сценаріїв 2-way (12+ комбінацій), time skew, регістр, перерване виконання.
